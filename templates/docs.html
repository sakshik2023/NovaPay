NovaPay API reference

REST + JSON. Amounts are integers in paise (₹1 = 100). Base URL: {{ request.scheme }}://{{ request.get_host }}/v1

Authentication

HTTP Basic. Username = Key ID, password = Secret (create keys in the dashboard). Secrets are stored hashed.

curl -u np_test_xxx:sk_xxx {{ request.scheme }}://{{ request.get_host }}/v1/ping

Errors

{ "error": { "code": "BAD_REQUEST_ERROR", "field": "amount", "description": "Amount must be at least 100 paise (Rs 1)" } }

Codes: BAD_REQUEST_ERROR 400 · AUTHENTICATION_ERROR 401 · INVALID_STATE / ORDER_ALREADY_PAID 409 · ORDER_EXPIRED 410 · IDEMPOTENCY_KEY_REUSED 422 · RATE_LIMITED 429 (120 req/min per merchant; see X-RateLimit-Remaining)

Idempotency

Send Idempotency-Key: <unique string> on any POST. A retry with the same key and body returns the original response (header Idempotent-Replayed: true) and never creates a second order, payment or refund. Same key + different body → 422.

Orders

POST /v1/orders
curl -u KEY:SECRET -H "Idempotency-Key: inv-1001" -H "Content-Type: application/json" \
  -d '{"amount": 149900, "currency": "INR", "receipt": "INV-1001",
       "description": "Python course", "callback_url": "https://shop.com/return"}' \
  {{ request.scheme }}://{{ request.get_host }}/v1/orders

→ 201 { "id": "order_9f2c…", "status": "created", "amount": 149900, "checkout_url": "/pay/order_9f2c…/" }
GET /v1/orders/{id} · /v1/orders?status=paid&count=25&starting_after=order_…

Payments

Customers normally pay on the hosted checkout (/pay/{order_id}/) so card data never touches your server. For sandbox testing you can also create payments directly:

POST /v1/payments
{ "order_id": "order_9f2c…", "method": "card", "card_number": "4111111111111111", "expiry": "12/30", "cvv": "123" }
{ "order_id": "order_9f2c…", "method": "upi",  "vpa": "success@upi" }
POST /v1/payments/{id}/otp   {"otp": "123456"}
GET /v1/payments/{id} · /v1/payments?status=captured&method=upi

Status flow: pending → captured | failed, then captured → partially_refunded → refunded.

Refunds

POST /v1/payments/{id}/refunds
{ "amount": 50000, "reason": "Customer request" }     // omit amount for a full refund

Total refunds can never exceed the captured amount, even under parallel requests.

Settlements & webhooks

GET /v1/settlements
POST /v1/webhooks/test

Events: payment.captured, payment.failed, order.paid, refund.processed, webhook.test. Return any 2xx to acknowledge; otherwise NovaPay retries after 10s, 1m, 5m, 30m, 2h.

# Verify (Python)
header = request.headers["X-NovaPay-Signature"]          # t=1712345678,v1=ab12…
t, v1 = [p.split("=")[1] for p in header.split(",")]
expected = hmac.new(WEBHOOK_SECRET.encode(), f"{t}.{request.body.decode()}".encode(), hashlib.sha256).hexdigest()
ok = hmac.compare_digest(v1, expected) and abs(time.time() - int(t)) < 300

Redirect signature

After payment the customer returns to your callback_url with order_id, payment_id, status, signature where signature = HMAC_SHA256(webhook_secret, order_id + "|" + payment_id). Always verify it, then confirm the status with GET /v1/payments/{id}.
